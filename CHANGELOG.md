# Changelog

## 0.2.0

### Added

- **Per-source LLM extraction layer** (#25). At intensity 3+, a new extraction phase runs between scraping and writing, using an LLM to extract key claims, data points, named entities, comparisons, recommendations, and criticisms from each source. The writer receives this structured data alongside raw source URLs, producing higher-fidelity reports.

- **Dynamic gap queries** (#21). When the researcher needs more sources (either to hit the intensity target or to address reviewer REVISE feedback), gap queries are now generated by an LLM with full context about what is already found, what the reviewer flagged, and what queries have already been executed. Falls back to template queries at intensity 1-2 or on LLM failure.

- **Supervisor keyword search queries** (#26, #22). The supervisor now returns structured `search_queries` blocks in its plan output, optionally using keyword-heavy Google-style searches to reduce zero-yield searches. Falls back gracefully to template queries if parsing fails.

- **CI pipeline**. GitHub Actions workflow runs the test suite on push and PR, locked to Python 3.10.

### Fixed

- **`--no-review` flag wired up** (#16). Previously the `--no-review` flag was parsed but not passed to `build_research_graph`, so reviewer ran regardless. Now properly skips review at all intensity levels.

- **Provider prefix stripping warning** (#17, #28). Model names like `openai:gpt-4.1` have their prefix silently stripped because all requests route through the configured DeepSeek base URL. ORA now emits a warning explaining this, and misleading help text referencing provider prefixes has been corrected.

- **Researcher gap queries run on REVISE even when min sources met** (#20, #27). Previously the researcher would skip gap queries if `min_sources` was already satisfied, missing reviewer-requested follow-ups. Now gap queries run whenever the reviewer sends a REVISE, regardless of source count.

- **Source doubling on re-loop**. Sources were being accumulated across graph loop iterations instead of per-invocation, causing duplicate entries. Fixed with per-invocation state management.

- **URL deduplication before scraping** (#24). Search result URLs are now pre-filtered to remove duplicates already seen in previous researcher rounds, and hostile-domain URLs (e.g., reddit.com) are filtered out before scraping begins.

- **Reviewer progress events**. The reviewer now emits progress events ("auditing draft report", "PASS" / "REVISE") so live-progress output shows review activity instead of a blank gap between writing and completion.

- **Fixed intensity table rendering** in README and CLI `config` output.

### Changed

- **Python 3.10 lock**. Pinned to Python 3.10 in CI and `requires-python` to avoid incompatibilities with the LangChain/LangGraph ecosystem on 3.11+.

- **Removed docs/superpowers** from repository tracking. Implementation plans and specs are now tracked only in Git history.

- **Improved contributor onboarding** with first-time contributor workflow in CONTRIBUTING.md.

## 0.1.0

Initial public release of ORA.

- Multi-agent research CLI.
- PyPI package name `open-research-agent`, with `open-research-agent` as the primary CLI command and `ora` as an alias.
- Research planning flow.
- Configurable intensity levels 1-5.
- Firecrawl search and scrape integration.
- DeepSeek-backed planning, research, writing, and review agents.
- Optional adversarial review for higher-intensity research.
- Local markdown report output.
